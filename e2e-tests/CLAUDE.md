# e2e-tests — инварианты

Отдельный npm-проект: сквозные сценарии в браузере через реальную admin-panel. Playwright. Запуск — `make test-e2e`, отчёт — `make e2e-report`.

## Главное правило
**Не импортировать ничего из `backend/src` и `frontend/src`.** Только браузер и HTTP. Свой `package.json`, свой tsconfig.

## Версия Playwright
`@playwright/test` в `package.json` обязан совпадать с тегом базового образа в `e2e-tests/Dockerfile` (`mcr.microsoft.com/playwright:v1.55.0-jammy`). При рассинхроне Playwright откажется стартовать. Меняешь одно — меняй второе.
Браузеры уже в образе, `playwright install` запускать не нужно.

## Селекторы
Только `data-testid` из реестра `docs/api/contract.md`, раздел 9. **Никаких CSS-классов, текстовых подписей и позиционных селекторов** — вёрстка и тексты будут меняться, реестр заморожен вместе с контрактом. Нужного testid нет — согласовать добавление в реестр, а не изобретать локально.

## Подготовка данных
Через API (`request`-фикстура), а не кликами по интерфейсу. Сценарий проверяет UI, а не скорость сидирования. Исключение — когда именно создание через форму и есть предмет теста.
База — `linkboard_test`, очистка в `global-setup.ts` и между тестами тем же хелпером, что в `api-tests`.
Адреса только из env: `BASE_URL` (в контейнере `http://frontend:3000`), `API_URL` (`http://backend:8080`).

## Борьба с флаками
- Только web-first assertions Playwright с автоожиданием (`await expect(locator).toHaveText(...)`). **`waitForTimeout` запрещён.**
- Клик по редиректу пишется асинхронно после 302 — счётчик в UI проверять ассертом с ретраем, а не паузой.
- `retries`: 0 в разработке, максимум 1 на стадии стабилизации. `trace: 'on-first-retry'`, `video: 'retain-on-failure'`.
- Критерий приёмки спринта — три зелёных прогона `make test-e2e` подряд. Пойманный флак либо чинится сразу, либо уходит в карантин через `test.fixme` с заведённым тикетом; молча ретраить нельзя.

## Что проверять
10 сценариев из `docs/plans/linkboard.md`, раздел 5.4, и `docs/testing/coverage-matrix.md` (префикс `E2E-`). Пересечения с `api-tests` допустимы там, где e2e проверяет именно путь через UI, а не логику API.

## Запуск
`npx playwright test` — one-shot, контейнер завершается, exit code пробрасывается в `make`. HTML-отчёт пишется в `playwright-report/`, смонтированную наружу.
